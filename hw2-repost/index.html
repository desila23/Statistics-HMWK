01 / THE IDEA

Different keys.
Different assumptions.

Encryption turns readable plaintext into ciphertext. Decryption uses a key to reverse the process. The important question is what an attacker can learn without that key.

SYMMETRIC

Caesar: one shared shift

Alice and Bob both know a number k. Alice moves every English letter forward by k places; Bob moves it back. Letters are indexed A = 0 through Z = 25. The alphabet wraps around, so Z shifted by 1 becomes A.

c = (m + k) mod 26 ↔ m = (c − k) mod 26

There are only 26 possible shifts. More importantly, the same plaintext letter always becomes the same ciphertext letter, preserving language patterns.

PUBLIC-KEY HYBRID

ECC: agree on a symmetric key

Bob keeps a private scalar d and publishes the point Q = dG. Alice uses a fresh ephemeral scalar r to derive a shared ECDH secret. AES-GCM then encrypts the message.

rQ = r(dG) = d(rG) = dR

This is hybrid encryption: ECC establishes the secret, HKDF derives an AES key, and AES-GCM encrypts and authenticates the bytes.

How this extends the previous homeworks ＋

Homework 1 used y² = x³ + 7 modulo 17 to illustrate point arithmetic. Here the field prime is p = 2²⁵⁶ − 2³² − 977, with the standard generator and subgroup order of secp256k1. These are different curves. The previous Homework 2 derived Ethereum addresses; deriving a public key or an address does not encrypt a message.

The new scheme is an educational ECIES-like construction, not an implementation of a standardized ECIES profile. Only the recipient key range is deliberately small. The ephemeral scalar is sampled from the full valid range.

Corpus preparation, sampling and what χ² means ＋

The full source files and their Project Gutenberg licenses are bundled. The analysis removes Gutenberg wrappers, tables of contents, Austen’s preface and bracketed illustration captions. It starts at the novels’ opening sentences, converts to uppercase, and keeps A–Z only. No test text is used to estimate the model. Letter probabilities use add-one smoothing: pᵢ = (training countᵢ + 1)/(training letters + 26).

For each candidate shift k, undo the shift and compare its counts Oᵢ to expected counts Eᵢ = Lpᵢ. The score is:

χ2(k)=∑i=025(Oi−Ei)2Ei

We minimize this discrepancy. This is a ranking heuristic, not a hypothesis-test p-value. Small expected counts, dependent letters and checking 26 shifts make a naive significance interpretation inappropriate.

The optional bigram method uses add-one smoothed joint probabilities for 676 adjacent letter pairs in the training text. It minimizes −Σ log p(pair). Pairs cross removed spaces. No trained model proves that a plaintext is correct.

RESULTS → INTERPRETATION

Read the experimental design and its limits

We partition the held-out A–Z stream into disjoint 1,000-letter blocks, shuffle their indices with a seeded PRNG, and sample without replacement. A trial uses prefixes of the same block at all lengths, so comparisons are paired. Blocks do not overlap within a length; results across lengths are intentionally dependent. Changing the Caesar shift does not create a new linguistic sample: rotation only relabels the same candidate set.

Wilson intervals are binomial reference intervals for accuracy, not guaranteed coverage for correlated literary text. We sample one book by one author, not all English. Success can be lower for names, short text, technical language, other languages, deliberately unusual letter distributions or mismatched corpora. Even 100% on these trials does not mean universal success. The 1/26 ≈ 3.85% uniform-guess baseline is a reference probability, not another measured attack.

Why this search works

The private scalar is guaranteed to lie in 1…B. We test at most B points; if d is uniformly chosen, the expected number is (B + 1)/2. The default d is a fixed classroom example. This attack does not inspect language or letter frequencies.

The timer includes worker scheduling and, when enabled, presentation delays. It is a wall-clock demonstration, not a cryptographic benchmark. Stop and restart reruns from candidate 1.

Why real keys are different

Valid secp256k1 private scalars lie in 1…n−1, where n is the generator’s order. That gives approximately 2²⁵⁶ choices, rather than a few thousand.

Generic discrete-log attacks such as Pollard rho have roughly √n work; known-interval attacks can use baby-step giant-step or Pollard kangaroo. A full-strength key space is still infeasible to search with these classical methods. We do not extrapolate exact real-world attack times from this toy run.

05 / COMPARISON & CONCLUSIONS

Two attacks.
Two different explanations.

Caesar exposes the structure of a language. The restricted ECC scheme exposes a searchable key interval. These experiments answer different questions.

PropertyCaesar ciphersecp256k1 hybrid scheme
ModelSymmetric substitution.Public-key agreement + symmetric authenticated encryption.
KeysSame secret shift k for both parties.Private d / public Q; fresh sender r / R; derived AES key K.
EncryptionAdd k modulo 26 to each letter index.ECDH rQ → HKDF-SHA-256 → AES-256-GCM.
DecryptionSubtract k modulo 26.ECDH dR → same K → verify tag and recover UTF-8.
Key space26 shifts (25 non-identity).Here: B possible recipient keys. Normally: n−1 ≈ 2²⁵⁶.
Language dependenceFrequency scoring depends on a suitable language model.Key search and tag verification do not depend on the language.
Exhaustive searchAll 26 decryptions are trivial; ranking selects one.Small B is searchable; normal key space is infeasible.
RandomnessNo fresh randomness: fixed k gives fixed ciphertext.Fresh full-range r, 32-byte HKDF salt, 12-byte GCM nonce.
Statistical propertiesPreserves frequency histogram up to rotation, repetitions, spaces and punctuation.AES ciphertext conceals simple language frequencies, but envelope length reveals UTF-8 message length.
Security limitsNo authentication; small space and language leakage.Deliberately weak d; demo protocol; no authenticated sender identity or production audit.

More letters help a statistical guess. Longer passages tend to resemble the training distribution more closely, reducing ambiguity between shifts. The measured success rate and its failures show how much that helps on the selected test book.

More possible keys make enumeration harder. ECC recovery here is exact once a public point matches. AES-GCM then checks that the recovered key decrypts the envelope. A language model plays no part.

Random-looking output is not a security proof. Balanced bits or high observed entropy cannot compensate for a tiny secret-key space. AES-GCM authentication detects an altered envelope under the established key, but this page does not authenticate the sender or protect against public-key substitution.
